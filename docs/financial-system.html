حساب العمولة — الطريقة النظيفة

  • تجميد (Snapshot): النِّسب تُخزَّن وقت الإنشاء في سطر الطلب — لا تتأثّر بتغيير الإعدادات.
  • الباقي (Residual): أرباح السائق = المتبقّي بعد الفليت والمكتب → الجمع دائماً صحيح.
  • وحدات صغرى صحيحة + توزيع الباقي على طرف محدَّد (لا بتر عشوائيّ).
  • دالّة نقيّة تغطّي كلّ الأنواع (عامّ/مكتب/مالك سيّارة/مخصّص) بحارس default.
totalAmount = FARE − discount fleet = round(FARE × rate_fleet) office = round(FARE × rate_office) driver = totalAmount − fleet − office // الباقي assert(fleet + office + driver == totalAmount)
قاعدة: التقسيم واحد مهما كانت طريقة الدفع؛ النقديّ/الإلكترونيّ يغيّران التحصيل فقط.

ضمانات السلامة

ذرّيّة

معاملة DB واحدة تغلّف كلّ التحريك + قيوده — لا transactions متداخلة، لا فشل جزئيّ.

منع التكرار

idempotency_key من مرجع الطلب/الدفعة — إعادة المحاولة آمنة.

توازن

Σ مدين = Σ دائن لكلّ عملة، وإلا تُرفض.

آلة حالة

الانتقالات بتحديث شرطيّ (WHERE status=…) → لا ازدواج.

قابليّة المطابقة

مجموع القيود = الأرصدة دائماً + تقرير يوميّ.

عملة لكلّ قيد

لا اختلاط عملات في معاملة واحدة.

خطّة الهجرة التدريجيّة

  • ١. بناء جداول الدفتر + خدمة LedgerService مرجعيّة في طبقة Core (دون لمس خدمات الموبايل).
  • ٢. كتابة دالّة العمولة النقيّة + اختباراتها لكلّ الحالات.
  • ٣. تشغيل الدفتر بالتوازي (shadow) مع النظام الحاليّ والمطابقة قبل التبديل.
  • ٤. تحويل نقاط المال (شحن/إكمال/سحب) لتكتب عبر الدفتر، ثمّ جعل Redis إسقاطاً.
